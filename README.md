# HFC — HypoFracCalc

**HFC (HypoFracCalc)** — веб-калькулятор клинической радиобиологии для дистанционной лучевой терапии фотонными пучками с прозрачной и отслеживаемой доказательной базой.

Проект вырос из полезных клинических идей, реализованных в `hypo-calc`, но HFC разрабатывается как независимая система со следующими принципами:

- биологические параметры привязаны к конкретным клиническим исходам, а не только к органу;
- для каждого параметра сохраняется источник;
- явно отображаются неопределённость и ограничения применимости;
- математическое ядро, доказательная база и пользовательский интерфейс разделены;
- пользовательские значения сохраняются как отдельные переопределения и не изменяют доказательную базу;
- расчёты должны быть воспроизводимыми и пригодными для аудита.

> HFC разрабатывается как инструмент поддержки клинических решений и независимой радиобиологической проверки для специалистов лучевой терапии. Это **не система назначения лечения**.

## Раздел «О сайте»

Отдельная вкладка «О сайте» объясняет:

- зачем создаётся HFC;
- почему биологические параметры должны быть связаны с конкретными клиническими исходами и источниками;
- почему HFC рассматривается как инструмент поддержки клинических решений, а не система назначения лечения;
- как устроено разделение между формулами и доказательной базой;
- какой статус имеет текущий набор данных.

На этой же странице автоматически формируется список литературы из реестра `src/data/evidence/v0.1/sources.ts`. Поэтому отображаемая библиография соответствует источникам, которые действительно используются или цитируются текущей доказательной базой HFC. Для источников с DOI или PMID доступны ссылки на публикацию или PubMed.

## Математическое ядро

Базовая линейно-квадратичная модель:

```
BED = n d (1 + d/(α/β))

EQDx = n d (d + α/β)/(x + α/β)
```

Для EQD₂:

```
x = 2 Gy
```

Реализованы:

- физическая доза;
- BED;
- EQDx / EQD₂;
- обратный расчёт дозы за фракцию для заданного EQD;
- Thames Hm для неполного восстановления;
- функции поправки на общую продолжительность лечения;
- предупреждения об экстраполяции LQ-модели при высоких дозах за фракцию;
- анализ чувствительности по 95% ДИ α/β.

Математическое ядро не зависит от React и пользовательского интерфейса.

## Модель доказательных параметров

Биологические параметры не зашиваются непосредственно в формулы или интерфейс.

Текущий черновой набор данных содержит:

- α/β для конкретных клинических исходов;
- 95% ДИ, где он опубликован;
- уровень поддержки оценки;
- предпочтительные, альтернативные и неавтоматические значения;
- DOI/PMID и библиографию;
- сведения об области применимости;
- T½ восстановления;
- Dprolif и Tk в единицах EQD₂.

Уже курированы данные для:

- биохимического контроля при раке предстательной железы — Vogelius & Bentzen 2020;
- поздней токсичности прямой кишки — CHHiP / Brand et al. 2021;
- поздней мочеполовой токсичности — CHHiP / Brand et al. 2023;
- рака молочной железы — FAST и FAST-Forward, включая 10-летние данные 2026 года;
- опухолевого контроля и поздних эффектов в области головы и шеи;
- NSCLC;
- лучевого пневмонита и фиброза лёгкого;
- поздних осложнений кишечника;
- орального мукозита;
- кожных и подкожных поздних эффектов;
- полного патоморфологического ответа при раке пищевода;
- лучевой миелопатии спинного мозга.

**Опубликованное число не становится значением по умолчанию автоматически.**

Например, для спинного мозга в текущем наборе есть существенно различающиеся опубликованные человеческие оценки α/β. Поэтому HFC не выбирает одно значение самостоятельно: пользователь должен явно выбрать источник или ввести своё значение.

Документация набора данных:

## Клинические ограничения

Отдельный слой HFC хранит клинические данные «доза–объём–риск» отдельно от α/β и формул BED/EQD₂.

Начальный набор основан на органоспецифических публикациях HyTEC и включает:

- зрительные пути;
- головной мозг;
- спинной мозг.

HFC различает:

- планировочную границу;
- точку риска;
- наблюдательный порог.

Это принципиально важно: например, V12 головного мозга, связанный с определённой вероятностью радионекроза, не должен автоматически становиться универсальным ограничением плана.

Для каждой записи сохраняются метрика, число фракций, риск, наличие предшествующего облучения и первичный источник. Диапазоны, опубликованные источником, не сворачиваются в одно число.

Подробнее: [docs/CONSTRAINTS.md](docs/CONSTRAINTS.md).

## Пользовательские значения

В поддерживаемых сценариях пользователь может заменить параметр из доказательной базы собственным значением.

Такое значение:

- не изменяет доказательную базу;
- существует только внутри конкретного расчёта;
- явно отмечается как заданное пользователем;
- может сопровождаться обоснованием.

Это позволяет использовать локальный протокол или проводить анализ чувствительности без потери информации об источнике.

## Неопределённость

HFC пока рассчитывает **однопараметрический анализ чувствительности**, а не полную клиническую неопределённость.

Для α/β с опубликованным 95% ДИ расчёт повторяется на его границах.

Если 95% ДИ α/β достигает или пересекает 0 Гр:

- BED становится неограниченным при α/β → 0;
- верхняя граница диапазона чувствительности BED считается неограниченной;
- для EQD₂ используется конечный предел при α/β → 0+.

В модуле сравнения режимов диапазон для ΔEQD₂ считается коррелированно: одна и та же граница α/β одновременно применяется к обоим сравниваемым режимам.

## Перерывы в лечении v0.2-dev

Модуль основан на:

- RCR *The timely delivery of radical radiotherapy*, 4-е издание;
- *Basic Clinical Radiobiology*, 6-е издание, 2025.

Приоритет логики:

1. по возможности сохранить исходную общую продолжительность лечения и дозу за фракцию;
2. использовать лечение в выходные дни;
3. при допустимости рассмотреть две фракции в сутки;
4. только если ускоренная компенсация невозможна — рассматривать изменение биологической дозы.

### Календарь лечения

В текущей ветке модуль умеет строить курс по реальным датам:

- дата начала лечения;
- начало и конец перерыва;
- стандартный график понедельник–пятница;
- плановые нерабочие даты;
- вариант без компенсации;
- лечение в выходные;
- дни с двумя фракциями.

Общая продолжительность лечения считается как **прошедшее календарное время между первой и последней фракцией**, а не как число дат включительно. Это проверяется регрессионным тестом на конвенции RCR: стандартный семинедельный курс **70 Гр / 35 фракций = 46 дней**, а перенос пяти пропущенных фракций на следующую рабочую неделю даёт **53 дня**.

### Репопуляция опухоли

Явно учитываются:

- RCR: минимальный интервал между двумя фракциями в сутки — **6 ч**;
- BCR 2025: желательно использовать максимально практичный интервал — около **8 ч и более**, когда это возможно;
- RCR: две фракции в сутки не рекомендуются, если доза за фракцию существенно выше **2,2 Гр**;
- линейная поправка Dprolif получает предупреждение при значительном удлинении общей продолжительности лечения.

Первое автоматически выбираемое значение временной поправки:

```
HNSCC
Dprolif = 0.80 Gy EQD2/day
95% CI  = 0.50–1.10
Tk      = 21 days
```

Решатель компенсации дозой восстанавливает **эффективный EQD₂ опухоли** для заданной фактической продолжительности лечения и числа оставшихся фракций.

### Органы риска

HFC теперь может одновременно добавить до **5 независимых оценок органов риска** и для каждой отдельно рассчитать изменение BED/EQD₂ выбранной дозовой метрики.

Принципы:

- доза на орган риска не приравнивается к предписанной дозе;
- пользователь выбирает дозовую метрику: Dmax, D0.03cc, D0.1cc, D1cc, D2cc, среднюю дозу или собственную дозовую метрику;
- объёмная метрика Vx намеренно не используется в этом расчёте, потому что её нельзя корректно преобразовать как дозу за фракцию;
- пользователь вводит дозу на выбранную метрику за фракцию;
- α/β выбирается для конкретного клинического исхода;
- при двух фракциях в сутки используется T½ и поправка на неполное восстановление;
- диапазон или нижняя граница T½ не превращаются автоматически в точечное значение;
- для компенсации увеличением дозы после перерыва доза на орган риска либо вводится явно, либо пользователь отдельно включает пропорциональное масштабирование как допущение.

Этот расчёт **не является автоматической проверкой DVH-ограничения**. Полученный BED/EQD₂ должен сопоставляться с клинически подходящей дозовой метрикой и соответствующим ограничением доза–объём.

Подробнее: [docs/TREATMENT_GAP.md](docs/TREATMENT_GAP.md).

## Повторное облучение v0.2-dev

Модуль повторного облучения реализует скалярную оценку кумулятивной эквивалентной дозы для **одной и той же дозовой метрики** во всех курсах.

Основные принципы:

- классификация сценария по ESTRO–EORTC: тип I, тип II или повторное облучение вне определения повторного облучения ESTRO–EORTC;
- каждый курс пересчитывается в BED и EQD₂ до суммирования;
- для выбранного клинического исхода одно и то же α/β используется последовательно во всех курсах;
- физические дозы показываются только для аудита и не используются как количественная кумулятивная доза на орган риска;
- поддерживаются Dmax, D0.03cc, D0.1cc, D1cc, D2cc и пользовательская дозовая метрика;
- объёмные метрики Vx/Dmean не суммируются скалярно;
- качество предыдущих данных и пригодность регистрации хранятся отдельно;
- доступны прямое точечное суммирование, суммирование в области перекрытия, консервативный околомаксимальный сценарий и документирование предполагаемого трёхмерного подхода;
- реальное воксельное трёхмерное суммирование в v0.1 ещё не выполняется;
- восстановление ткани **никогда не выводится автоматически из временного интервала**;
- для повторного SBRT позвоночника добавлена отдельная проверка факторов HyTEC с сохранением доказательного контекста, связанных с более низким риском лучевой миелопатии;
- эта проверка использует собственную опубликованную основу EQD₂ с α/β = 2 Гр и не наследует пользовательскую «скидку на восстановление» из общего калькулятора повторного облучения;
- если восстановление учитывается, пользователь явно задаёт процент снижения вклада предыдущей эквивалентной дозы и обязательное обоснование;
- можно рассчитать остаточный математический EQD₂-бюджет, но HFC не подставляет кумулятивную клиническую границу автоматически.

Основные методические источники:

- ESTRO–EORTC consensus 2022;
- RCR *Principles of reirradiation*, 2024;
- ESTRO Reirradiation Focus Group cumulative-dose consensus, 2026;
- ReCOG consensus, 2026;
- ReCOG case-based implementation guide, 2026.

Подробнее: [docs/REIRRADIATION.md](docs/REIRRADIATION.md).

### Проверка HyTEC для позвоночника

Для одного предыдущего курса и одного текущего курса SBRT в 1–5 фракций HFC может отдельно проверить четыре опубликованных фактора HyTEC, связанных с более низким риском лучевой миелопатии:

- кумулятивный Dmax оболочки спинного мозга ≤70 Гр EQD₂₂;
- Dmax текущего SBRT ≤25 Гр EQD₂₂;
- отношение текущего SBRT EQD₂₂ к кумулятивному EQD₂₂ ≤0,5;
- интервал между курсами ≥5 месяцев.

Проверка включается только при явном подтверждении, что введённая метрика действительно является **Dmax оболочки спинного мозга (thecal sac)**. Она не трактуется как автоматическое разрешение на лечение: HyTEC описывает эти значения как факторы, связанные с более низким риском, а не как абсолютные пределы толерантности.


## Аудит расчёта

Экспортируемый JSON-аудит HFC реализован для Быстрого EQD, Сравнения режимов, Перерывов в лечении и Повторного облучения.

Кнопка **«Скачать аудит JSON»** на поддерживаемых страницах сохраняет:

- версии расчётного ядра, схемы аудита и доказательной базы;
- исходные режимы, курсы, календарь и дозовые метрики, относящиеся к конкретному модулю;
- α/β, Dprolif/Tk и другие применённые параметры вместе с происхождением;
- BED/EQD₂ и сравнительные результаты;
- стратегии компенсации перерыва и все добавленные карточки органов риска с α/β, T½, дозовой метрикой и происхождением параметров;
- классификацию, восстановление и специальные проверки при повторном облучении;
- предупреждения;
- полные библиографические записи использованных методических и параметрических источников.

Аудит не требует персональных данных пациента.

Для тех же модулей доступен **печатный отчёт**: HFC открывает локально сформированную A4-страницу с входными данными, результатами, предупреждениями и источниками. Её можно распечатать или сохранить в PDF стандартной функцией браузера без отправки расчётных данных на внешний сервис.

Подробнее: [docs/AUDIT.md](docs/AUDIT.md).

## Ветки и `main`

`main` — стабильная рабочая ветка проекта, предназначенная для публикации официальной версии сайта.

Разработка ведётся в отдельных ветках возможностей и интеграционной ветке `develop`, после чего изменения проходят через запрос на слияние и автоматические проверки CI. Это позволяет не публиковать неподтверждённые изменения непосредственно на основной сайт.

После проверки релиза изменения попадают в `main`, а GitHub Pages собирает рабочий сайт именно из неё.

## Локальный запуск

Требуется Node.js 22+.

```bash
npm install
npm run dev
```

Проверка:

```bash
npm run typecheck
npm test
npm run build
```

## Публикация сайта

В репозитории есть рабочий процесс:

```
.github/workflows/deploy-pages.yml
```

После слияния изменений в `main` он:

1. выполняет проверку типов;
2. запускает тесты;
3. собирает сайт с помощью Vite;
4. публикует содержимое `dist/` через GitHub Pages.

В настройках репозитория GitHub Pages должен быть выбран источник **GitHub Actions**.

## Версионирование

Расчётное ядро и доказательная база версионируются независимо.

Пример:

```
Ядро HFC:         0.x
Набор данных:      2026.10-v0.1
```

Исторический расчёт в дальнейшем должен оставаться воспроизводимым после обновления доказательной базы.

## Текущий охват

Входит:

- дистанционная лучевая терапия мегавольтными фотонными пучками;
- сравнение режимов фракционирования на основе LQ-модели;
- моделирование перерывов лечения по реальным календарным датам;
- отдельная оценка выбранной дозовой метрики органа риска при компенсации перерыва;
- начальный каталог клинических данных HyTEC «доза–объём–риск»;
- скалярная оценка кумулятивного BED/EQD₂ при повторном облучении;
- явные пользовательские допущения о восстановлении в повторном облучении;
- экспорт структурированного JSON-аудита Быстрого EQD, Сравнения режимов, Перерывов в лечении и Повторного облучения;
- человекочитаемый A4-отчёт для печати или локального сохранения в PDF;
- биологические параметры с отслеживаемыми источниками.

Пока не входит:

- моделирование протонной терапии и RBE;
- модели мощности дозы для брахитерапии;
- автоматическая проверка DVH-ограничений при компенсации перерыва;
- воксельное суммирование EQD₂ из DICOM;
- автоматическая регистрация и трёхмерное накопление дозы при повторном облучении;
- автоматический выбор коэффициента восстановления или кумулятивной клинической границы;
- автономные клинические рекомендации или назначение лечения.

## Назначение и безопасность

HFC предназначен для квалифицированных специалистов лучевой терапии как прозрачный инструмент расчёта и поддержки клинических решений.

Для клинического применения необходимы:

- независимая проверка;
- локальное комиссионирование;
- документированная система управления;
- проверка применимых ограничений доза–объём;
- клиническое решение специалиста.

Математическая эквивалентность BED/EQD₂ сама по себе **не означает клиническую взаимозаменяемость режимов**.
