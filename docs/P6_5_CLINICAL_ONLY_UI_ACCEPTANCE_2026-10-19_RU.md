# HFC — P6.5: единый клинический дизайн и исправление контрастных рамок

**Дата:** 19.10.2026. **Основание:** утверждённый пользователем запрос, мобильный скриншот тёмной версии; работа ведётся в ветке `ui/p6-5-clinical-only-border-cleanup-20261019`.  
**Назначение:** исключительно UI/UX-полировка без пересмотра клинической, математической или научной составляющей.  
**Выпуск:** отдельный PR в `develop` с автоматической проверкой и визуальной приёмкой до интеграции.

## 1. Цель
Оставить единый **Clinical** визуальный язык сайта, убрать переключение Journal/Compact, устранить белёсую/двойную окантовку и привести светлую/тёмную цветовые схемы к единым границам, состояниям фокуса и плотности.

## 2. Функциональные требования

### UI-01 — единственный дизайн
- Из шапки удалить selector `Clinical / Journal / Compact`, связанный React-state и `DesignStyle`.
- Отказаться от CSS `html[data-design="journal"]`, `html[data-design="compact"]` и даже необходимости `data-design`.
- Прежнее значение `localStorage["hfc-design-style"]` удалить на запуске; даже `journal`/`compact` из старой версии не влияет на страницу.
- Оставить RU/EN, переключатель светлой/тёмной темы и сохранение `hfc-color-theme`.

### UI-02 — мобильная навигация и окантовки
- Исправить `.mobile-nav`: у sticky-wrapper не должно быть фонового светло-серого прямоугольника на тёмном фоне. Причина в исходном CSS: hardcoded `rgba(238, 242, 245, 0.94)` без dark override.
- У sticky-wrapper не должно быть дополнительного видимого бордера, только border у `.mobile-nav-trigger`.
- Тёмные границы чипа `Фотонная ДЛТ`, переключателя языка, навигации, меню и темы брать из `--hfc-border`, не из светлых `#cbd5da`/похожих констант.
- Не устранять доступность ради косметики: для клавиатуры обязательный видимый `:focus-visible`, Hover/active должны оставаться распознаваемыми.
- В тёмной теме обеспечить тёмные поверхности у очевидных legacy white cards, в частности summary и comparison legend.

### UI-03 — единообразие страниц
Пройти маршруты: Главная, Как пользоваться, Калькуляторы, Быстрый BED/EQD₂, Сравнение режимов, Подбор EQD₂, Коррекция курса, Интерактивный календарь, Перерывы в лечении, Повторное облучение, Методология, Clinical Constraints, OutcomeModels, Аудит JSON, О сайте. Не менять заголовки, вводы, вычисления, предупреждения или источники.

### UI-04 — адаптивность
- На 390 × 844 тёмная и светлая темы без белой внешней рамки вокруг меню и без документного горизонтального переполнения.
- На 1440 × 1000 убедиться, что меню остаётся доступным и панель управления чистая.
- Использовать Playwright capture всех 15 разделов на desktop + mobile light + mobile dark.
- Взять регрессию календаря, расчётов, export/replay, локализации RU/EN из существующего CI.

## 3. Критерии приёмки

1. [ ] В DOM нет selector `Вариант дизайна / Design variant`, нет `data-design`, нет сохранённого ключа `hfc-design-style` после инициализации.
2. [ ] Светлая/тёмная темы включаются и сохраняются после перезагрузки.
3. [ ] Computed background sticky-навигации совпадает с фоном сайта как в light, так и dark, тёмный фон действительно тёмный; верхние элементы не имеют почти белых границ в dark.
4. [ ] Переключение мобильных разделов и RU/EN работает без горизонтального overflow.
5. [ ] Печатный календарь и audit PDF/JSON остаются неизменными, клинический release banner доступен на всех страницах.
6. [ ] Typecheck, Unit tests, Build, Browser QA и Visual QA GitHub Actions прошли.
7. [ ] Нет изменений в `src/core`, `src/evidence`, `src/data/evidence`, `src/workflows` или численных параметрах; evidence dataset остается `draft`.

## 4. Что намеренно не делаем
- Не меняем текст клинических предупреждений, не скрываем статус `draft`.
- Не вводим новые компоненты медицинского расчёта.
- Не меняем опубликованные BED/EQD₂, α/β, TCP/NTCP, OAR limits и scientific source records.
- Не делаем из визуального smoke test клиническую валидацию.
- Не объединяем с экспериментальным PR дизайна №55, он остаётся самостоятельной неутверждённой идеей.
