# P4 — безопасное разрешение источников репопуляции, BED/EQD₂ и пакет клинического рецензирования

**Дата:** 11 октября 2026 года. **Ветка:** `audit-p1-p2-scientific-review-20261008`, PR #60 (DRAFT). **Тип изменений:** fail-closed selection safety и научно-клиническое ТЗ. Это не клинический релиз и не решение задачи Hinata.

## 1. Два подтверждённых дефекта прежнего поведения

### P3-C07 — `deprecated` можно было использовать напрямую

`getRepopulationEstimates(endpointId)` ранее скрывал записи `status="deprecated"`, но `resolveRepopulationSelection(..., {selectionMode:"evidence",parameterRecordId})` принимал известный ID и возвращал число с предупреждением. Потребитель, указавший ID через сохранённую ссылку, тестовый сценарий или API, мог выполнить расчёт на исключённой модели. Проблемные записи:

- `dprolif-hn-various-bcr2025`: старый широкий H&N коэффициент 0,80 Gy_EQD2/day, Tk=21. Сам учебник BCR 2025 показывает такую пару, однако исходная работа Roberts 1994 не представляет всю неоднородную группу HNSCC. Запись оставлена только для научного архива и исторического сравнения.
- `dprolif-hn-larynx-bcr2025`: BCR 0,74 Gy_EQD2/day с диапазоном [0,30–1,20], но несоответствие первичной Robertson 1998 0,89 [0,35–1,43] по применённой модели остаётся неразрешённым; устаревший ID запрещён для новых расчётов.

**Исправлено на уровне выбора:** `resolveRepopulationSelection` выдаёт исключение при `status="deprecated"`, а список доступных к новому выбору записей исключает эти ID. Сами архивные коэффициенты, ссылки на источник, ДИ и классификация не удалены.

### P3-C03 — Hinata tBEDmax нельзя численно подставлять в модель EQD₂

Hinata et al. 2001, PMID 11383644 — параметр `gamma/alpha` опубликован как **BED Gy/day в time-adjusted BED**, где конечной величиной анализа является **максимум `tBED` в течение курса**, не всегда BED в конечную дату. Однако две записи HFC сохраняют исторический `basis:"EQD2"`, что позволяло ошибочно подставить `0,52/0,55` как Gy_EQD2/day. Отсутствие автоподстановки не защищало от явного выбора.

- `dprolif-medulloblastoma-bcr2025`: `gamma/alpha=0.52`, Tk=0.
- `dprolif-medulloblastoma-tk21-hinata2001`: `gamma/alpha=0.55`, Tk=21.

**Исправлено на уровне выбора:** обе записи исключены из нового списка и отклоняются разрешителем даже при известном ID и явной замене `Tk`. **Не введена** ошибочно-упрощённая численная конверсия или новый коэффициент. Исторические численные данные/CI/`basis` сохранены только для научного аудита, где в соответствующей документации прямо указан конфликт размерностей. Более ранний учебный пример показывает арифметическое расхождение конечных EQD₂-потерь на 2,2 Gy при формальном переводе 13,2 BED→11,0 EQD₂; это **не** воспроизведение исходного максимума `tBED` и не клиническая рекомендация.

## 2. Совместимость и предсказуемые эффекты

- Это **умышленное изменение runtime API**. Старые параметры в сохранённых расчётах/URL, вызывающие один из четырёх неразрешённых record ID, теперь выдадут ясную ошибку вместо дозового ответа. Клиентский интерфейс должен отображать эту ошибку и предложить иной источник либо осознанный ручной исследовательский расчёт. Не заменять ID автоматически другой моделью.
- **Все исходные коэффициенты α/β, CI, Dprolif, BED, EQD₂ и T½ остаются как были.** Исправление ограничено только выбором из научной библиотеки.
- `manual` остаётся доступным с исходным предупреждением, что пользователь сам вводит Dprolif и Tk; это допустимо **для исследовательского анализа чувствительности**, но само по себе не означает клиническую корректность и не является способом «утвердить» запрещённый ID. Результат должен сохранять `selectionMode:"manual"` без ложной связи с библиотечным record ID.
- Прежние регрессионные сценарии общего H&N 0,8/21 обновлены: те же учебные числа вводятся вручную, итоговые EQD₂ сохраняются с прежней арифметикой. Автозамена устаревшего источника не происходит.
- Список литературных оценок (`getRepopulationEstimates`) скрывает только четыре непригодные для данного калькулятора записи: **2 deprecated + 2 Hinata с неразрешённой размерностью**. Две последние сохранены как отдельные научные записи, но пока **нельзя использовать как EQD₂**.
- `evidenceManifest.releaseStatus="draft"`; `main`/`develop` не меняются; клинический выпуск недоступен.

## 3. Регрессионные сценарии P4

Автоматические тесты [`p4RepopulationEvidenceSelectionSafety.test.ts`](../tests/p4RepopulationEvidenceSelectionSafety.test.ts) проверяют:
1. Все 14 записей остаются в архиве, четыре unsafe ID отсутствуют в новом списке, `getPreferred...` их не выбирает.
2. Explicit evidence selection для каждого deprecated ID и каждой Hinata альтернативы завершается **исключением до получения дозы**, включая попытку задания другого `Tk`.
3. `buildTreatmentGapBaseline` не может собрать исходные или компенсированные EQD₂ для unsafe ID.
4. Ручной исследовательский сценарий 35×2 Гр, Tk21, 0,8 Gy_EQD2/day, +7 суток воспроизводит старую **дельту −5,6 Gy_EQD2** с `selectionMode:"manual"` и без library record ID.
5. Две исторические оценки Hinata остаются точными в dataset, но их применимость к Treatment Gap **не объявлена восстановленной**.

## 4. Независимое клиническое рецензирование — шаблон протокола

**Требуются две независимые подписи:** медицинского физика (не автора текущих расчётных тестов) и врача-радиотерапевта с профильным опытом. В данном PR подписи **не получены**.

| Проверяемый объект | Действие рецензента | Критерий принятия |
|---|---|---|
| Выбор параметров | Проверить списки endpoint/parameter ID, запрет 4 unsafe ID, ручной ввод, предупреждения | Никакой устаревший или BED-only ID не выдаёт клинически выглядящий автоматический EQD₂ |
| LQ BED/EQD₂ | Сверить внешним расчётом n, d, α/β, крайние и отрицательные интервалы CI | Совпадают расчёт, размерности, округление и документированные границы применимости |
| Репопуляция и Tk | Разделить BED K, EQD₂ Dprolif, фиксированный/отсутствующий Tk, влияние OTT | Нет подстановки чужой размерности или молчаливого Tk по «разделительной дате» исследования |
| Перерывы | Задать сценарии без перерыва, +1 сут, +7 сут, +21 сут, BID и weekend | Числа + предупреждения соответствуют независимой проверке, длинные перерывы помечены как нестандартная экстраполяция |
| ОАР и токсичность | Проверить endpoint-specific ограничения для выбранной популяции и техники | Нет автоматического переноса опухолевых и нормотканевых α/β, нет ложной безопасности нормальных тканей |
| Ошибочный выбор | Восстановить из URL или объекта ранее сохранённый `deprecated`/Hinata ID | Система предсказуемо останавливает расчёт и предоставляет человеку понятный путь для пересмотра |
| Выпуск | Проверить source provenance, актуальные `G1–G6` и локальный commissioning | Все обязательные пункты формально подписаны либо релиз остаётся черновым |

**Бланк подписания:** `Reviewer name / role / organization / independent from development / version & SHA / source list / evaluated cases / pass-fail remarks / deviations / date / signature`. Ни один пункт нельзя считать подписанным потому, что выполнился Vitest или GitHub Actions.

## 5. Что остаётся после защитного исправления

- **P3-C07:** риск *применения* deprecated ID устранён на уровне resolver, но нужно проверить отображение ошибок в конечном UI и исторические saved links. Потребитель API теперь получает исключение — это безопасное изменение поведения, требующее пользовательской проверки.
- **P3-C03:** риск *прямого применения* BED-only Hinata 0,52/0,55 как EQD₂ предотвращён. Исходная математическая модель `tBEDmax`, её регрессии, максимизация по времени и самостоятельная научная валидация **не реализованы**; эта научная задача остаётся **OPEN**.
- **G1–G5** и часть **G6** всё ещё OPEN; **G7 BLOCKED**. Не проводить `develop→main`, не публиковать как клиническое ПО, не подменять отсутствующие reviewer signatures.

**Следующий технический шаг:** в UI отобразить сообщение о запрещённой записи без фатального падения страницы и протестировать загрузку сохранённого ID; после независимого ревью — решить, реализовывать ли отдельный `BED/tBEDmax` workflow или оставить обе модели только в научном архиве.
