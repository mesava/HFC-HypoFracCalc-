# Аудит расчётов HFC — v0.1

## Цель

Клинический радиобиологический расчёт должен быть воспроизводимым не только по итоговому числу, но и по исходным данным, выбранным параметрам, доказательной базе и допущениям.

Первый экспортируемый аудит реализован для модуля **«Повторное облучение»**.

## Формат

На странице результата доступна кнопка:

```
Скачать аудит JSON
```

Файл содержит структурированную запись расчёта и предназначен для:

- независимой проверки;
- сохранения вместе с локальной документацией;
- последующего сравнения расчётов;
- воспроизведения результата после обновления HFC;
- машинного анализа без извлечения данных из интерфейса.

## Что сохраняется

В версии v0.1 экспортируются:

- версия схемы аудита;
- версия расчётного ядра HFC;
- версия доказательной базы и дата отсечения данных;
- дата и время формирования файла;
- идентификатор и название клинического исхода;
- выбранное α/β;
- способ выбора α/β: доказательная база или пользовательское значение;
- идентификатор записи и источника, если они есть;
- дозовая метрика;
- классификация повторного облучения;
- наличие геометрического перекрытия;
- наличие опасения по кумулятивной токсичности;
- качество предыдущих данных;
- пригодность регистрации;
- способ оценки кумулятивной дозы;
- все предыдущие курсы и текущий курс;
- интервалы между курсами;
- ручные допущения о восстановлении и их обоснование;
- BED и EQD₂ каждого курса;
- скорректированный вклад каждого предыдущего курса;
- кумулятивные BED и EQD₂;
- предупреждения;
- остаточный EQD₂-бюджет, если пользователь его рассчитывал;
- специальная проверка HyTEC для повторного облучения спинного мозга, если она применялась;
- библиографические записи методических и параметрических источников.

## Почему источники копируются в файл

В отчёте сохраняются не только идентификаторы источников, но и их библиографические записи.

Это нужно для того, чтобы исторический расчёт оставался понятным даже после обновления реестра доказательной базы.

## Версионирование

В файл входят два независимых номера:

```
engineVersion
evidence.datasetVersion
```

Также сохраняется:

```
schemaVersion
```

Версия схемы аудита относится к структуре JSON-файла и может меняться независимо от расчётного ядра.

## Что намеренно не сохраняется

HFC не требует и не добавляет в файл:

- ФИО пациента;
- дату рождения;
- номер истории болезни;
- идентификаторы медицинской информационной системы.

Текущий аудит рассчитан на радиобиологические параметры и методику расчёта, а не на хранение персональных данных.

Если пользователь самостоятельно включает идентифицирующие данные в свободный текст будущих версий, ответственность за их обработку должна определяться локальными правилами учреждения.

## Время формирования

Поле `generatedAtIso` добавляется только в момент нажатия кнопки экспорта.

Оно не участвует в математическом расчёте. При фиксированной временной метке сама сериализация детерминирована и проверяется тестом.

## Ограничения v0.1

Пока экспорт реализован только для повторного облучения.

Следующие этапы:

1. общий формат аудита для Быстрого EQD;
2. экспорт сравнения режимов;
3. экспорт расчёта перерыва лечения и календаря;
4. человекочитаемый печатный отчёт;
5. контрольная хеш-сумма записи;
6. возможность импортировать JSON обратно в HFC для воспроизведения расчёта.

## Безопасность

Экспортированный файл документирует расчёт поддержки клинического решения.

Он не является:

- назначением лечения;
- автоматическим заключением о безопасности;
- заменой независимой проверки;
- заменой клинического протокола или ограничений доза–объём.
