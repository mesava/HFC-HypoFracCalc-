## 2. Второй арифметический контроль (независимый от функций приложения)

**Исключительно условный учебный пример, не пациентский расчёт.**

Случай `n=30`, `d=2 Gy`, `alpha/beta=10 Gy`, `OTT=45 days`, `Tk=21 days`, опубликованная Hinata ставка `gamma/alpha = 0.55 Gy_BED/day`. При равных фракциях:

```
BED_raw = n*d*(1 + d/(alpha/beta)) = 30*2*1.2 = 72 Gy_BED
EQD2_raw = BED_raw/(1+2/(alpha/beta)) = 60 Gy_EQD2
activeDays = max(0,45-21) = 24 days
Delta_BED = 24*0.55 = 13.2 Gy_BED
Converted illustrative Delta_EQD2 = 13.2/1.2 = 11.0 Gy_EQD2
Incorrect treating 0.55 as EQD2/day: 24*0.55 = 13.2 Gy_EQD2
Difference = 2.2 Gy_EQD2
```

Счёт проверен альтернативной прямой арифметикой отдельно от функций HFC. Сам по себе пересчёт конечной BED **не эквивалентен публикации Hinata**, поскольку их модель использует **максимум временной BED**.

Второй условный «прерывистый» тест для `alpha/beta=10`, `2 Gy/fraction`, `gamma/alpha=0.55 Gy_BED/day`, `Tk=0`, моменты выдачи 1-й, 2-й и 3-й фракции `t=0,1,30 days`:

| Время (day) | Сумма физической дозы (Gy) | Условная tBED (Gy_BED) |
|---:|---:|---:|
| 0 | 2 | 2.40 |
| 1 | 4 | 4.25 |
| 30 | 6 | −9.30 |

**max=4.25 Gy_BED при t=1**, а не финальные −9.30. Это только математический демонстратор различия `max_t` vs `t=end`, не полный воспроизведённый алгоритм или клинически реалистичный протокол.

### Вывод по научной модели tBEDmax

**Не мешает HFC архитектурно**, если реализована **отдельно**, с discriminated union структурой единиц, а не общим полем `rateGyPerDay`:

- `{modelKind:"linear-OTT-EQD2", dProlifGyEqd2PerDay, tkDays, ...}` — существующий модуль Treatment Gap, отдельные доказательные ограничения.
- `{modelKind:"time-BED-maximum", gammaOverAlphaGyBedPerDay, tkDays, alphaBetaGy, fractionTimesAndDoses, ...}` — **будущий research-only** модуль, выдающий траекторию `tBED(t)`, `maximum tBED`, дату максимума и самостоятельный контекст источника.
- Межмодельный перевод запрещён по умолчанию; `tBEDmax` не является просто EQD₂, полученным из итоговой BED и переведённым коэффициентом `1+2/(alpha/beta)`.
- Не подмешивать его в автоматический подбор компенсации времени, нормативные constraints или заключение об эффективности/безопасности. Не публиковать как клинический модуль до точной проверки исходного PDF Eq.(1)–(3), границ времени и подтверждения методологии внешними специалистами.
- Возможный вариант **не реализовывать вообще**: оставить источник Hinata в научном архиве и использовать только независимые EQD₂/day источники, где воспроизводимо заданы параметры. Архитектурно это полностью допустимо.

## 3. Проверка обратной совместимости архивных JSON

**Исходный дефект:** публичный `AuditReplayView` при импорте действительно ловил любое исключение `inspectAuditDocument` и в русской локализации показывал «Не удалось проверить структуру audit JSON». Новый runtime resolver отклонял четыре запрещённых ID. Поэтому подписанный **целый** старый расчёт отображался как структурно ошибочный.

**Реализованное P4-R1 поведение:**

- Исходный audit envelope сначала проверяется SHA-256, а schema 1.0 читается с честным `legacy-unverified` без вымышленной криптографической гарантии.
- Для Treatment Gap inspect-only находит четыре unsafe source IDs: две `deprecated` головы/шеи и две `Hinata tBEDmax` модели.
- Импорт остаётся успешным, метаданные и результат проверки целостности показаны. Отдельная панель **«Сохранённый расчёт открыт, но повторный расчёт заблокирован»** содержит ID, класс риска и путь для ручного переосмысления сценария. Нет ни нового EQD₂, ни автоподстановки допустимого source ID.
- Сохранённые внутри JSON численные результаты не перезаписываются, но **самостоятельно не подтверждаются**. UI дополнительно показывает **два сохранённых поля EQD₂ в режиме только чтения** (плановое эффективное EQD₂ и изменение эффективного EQD₂ при перерыве) с прямой маркировкой «НЕ пересчитаны». Полный сохранённый audit JSON остаётся у пользователя; это **не возобновление клинической проверки** архива, не замена модели и не автоматический расчёт. Файл физически не удаляется.
- Если файл с SHA-256 изменён, импорт по-прежнему отклоняется **до** классификации источника. Исправный современный аудит с `manual` или поддерживаемым `evidence` по-прежнему пересчитывается и сравнивается без регрессии.

Тест-кейсы: [Vitest](../tests/auditReplayClinical.test.ts) ×4 подписанных unsafe ID + raw schema 1.0 + tampered SHA; [Playwright](../e2e/hfc.audit-replay-clinical.pw.ts) ×4 signed + raw + tampered + текущие незаблокированные модули.
