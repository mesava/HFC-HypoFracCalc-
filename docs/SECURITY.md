# Безопасность toolchain HFC

## Назначение

HFC является статическим браузерным приложением, однако его разработка и сборка зависят от Node.js, Vite, Vitest и связанных пакетов. Уязвимость в dev/build toolchain не означает автоматически уязвимость опубликованного статического сайта, но она важна для:

- рабочих станций разработчиков;
- CI;
- локального dev server;
- воспроизводимости и доверия к процессу сборки.

## Обновление 2026-10

После того как CI начал показывать npm advisory findings, toolchain был переведён на актуальную ветку Vite 8 и Vitest 5.

Зафиксированные верхнеуровневые версии:

```
Node.js                 >=22.12.0
Vite                    8.3.2
@vitejs/plugin-react    6.1.2
Vitest                  5.0.3
TypeScript              5.9.3
```

React в этой ветке намеренно не обновлялся функционально:

```
react       19.1.1
react-dom   19.1.1
```

## Причина обновления

В 2026 году были опубликованы несколько advisories для dev-server/test toolchain.

Среди релевантных примеров:

- Vite — CVE-2026-39363 / GHSA-p9ff-h696-f583: arbitrary file read через dev-server WebSocket; исправлено в ветке 7 начиная с 7.3.2 и в ветке 8 начиная с 8.0.5.
- Vite — CVE-2026-39364 / GHSA-v2wj-q39q-566r: обход `server.fs.deny`; исправлено в Vite 7.3.2 и 8.0.5.
- Vitest — CVE-2026-47429 / GHSA-5xrq-8626-4rwp: arbitrary file read/execution при определённых режимах UI/API; исправлено в 3.2.6 и 4.1.0.
- Vitest browser — CVE-2026-73653 / GHSA-p63j-vcc4-9vmv: обход ограничения файлового доступа; исправлено в 3.2.7, 4.1.10 и последующих ветках.
- esbuild — GHSA-gv7w-rqvm-qjhr: отсутствие integrity verification в Deno-модуле; исправлено начиная с esbuild 0.28.1.

HFC не использует Vitest Browser Mode в текущей конфигурации, но зависимость всё равно не должна оставаться на потенциально уязвимой ветке.

## CI policy

Обычный CI и сборка GitHub Pages теперь выполняют:

```
npm install
npm run audit:security
npm run typecheck
npm test
npm run build
```

`npm run audit:security` соответствует:

```
npm audit --audit-level=high
```

Таким образом, **high** и **critical** advisories блокируют CI и публикацию.

Moderate/low findings не игнорируются концептуально, но не блокируют сборку автоматически: для них требуется отдельная оценка реальной применимости к HFC.

## Dev-server

Локальный dev-server не следует публиковать наружу без необходимости.

В частности, разработчик не должен использовать `vite --host 0.0.0.0` на недоверенной сети просто для удобства. Опубликованный GitHub Pages сайт — статическая production-сборка и не использует Vite dev-server.

## Воспроизводимость зависимостей

Верхнеуровневые зависимости закреплены точными версиями.

Следующий шаг управления зависимостями — добавить и поддерживать lock-файл, после чего CI следует перевести с `npm install` на `npm ci`. До этого транзитивные зависимости могут изменяться между установками в пределах ограничений их родителей.

## Правило обновления

Обновление toolchain не должно объединяться с изменением радиобиологических формул или доказательных параметров в одном PR.

После каждого обновления обязательны:

1. typecheck;
2. полный unit-test suite;
3. production build;
4. npm security audit;
5. проверка, что математические regression tests не изменились без объяснимой причины.
